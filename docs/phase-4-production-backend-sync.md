# Phase 4 Production Backend Sync

## Root Cause

Production create ticket fails at the RPC stage with:

```text
PostgrestException code=PGRST202 stage=rpc
public.create_ticket_with_attachments(...) not found in schema cache
```

`PGRST202` means PostgREST cannot find the requested function in its schema cache. For Phase 4 this points to production backend drift: either `supabase/migrations/20260630090000_phase_4_create_ticket_with_attachments.sql` has not been applied to production, or it was applied but PostgREST has not reloaded its schema cache.

The Flutter contract and repository migration match. Do not replace the RPC with a permanent direct insert path for tickets with attachments. The atomic RPC remains the production contract because storage uploads and attachment metadata must be reconciled transactionally.

## Flutter vs SQL Migration Contract

Flutter call site:

```dart
await supabaseClient.rpc('create_ticket_with_attachments', params: {
  'p_ticket_id': ticketId,
  'p_title': title,
  'p_description': description,
  'p_category': category,
  'p_attachments': attachments
      .map((attachment) => attachment.toManifestJson())
      .toList(growable: false),
});
```

SQL migration contract:

```sql
create or replace function public.create_ticket_with_attachments(
  p_ticket_id uuid,
  p_title text,
  p_description text,
  p_category text,
  p_attachments jsonb default '[]'::jsonb
)
returns uuid
```

Contract comparison:

| Field | Flutter | SQL | Status |
| --- | --- | --- | --- |
| RPC name | `create_ticket_with_attachments` | `public.create_ticket_with_attachments` | Match |
| `p_ticket_id` | UUID string generated by app | `uuid` | Match |
| `p_title` | trimmed `String` | `text` | Match |
| `p_description` | trimmed `String` | `text` | Match |
| `p_category` | trimmed `String` | `text` | Match |
| `p_attachments` | `List<Map<String, dynamic>>` serialized as JSON | `jsonb` array, default `[]` | Match |
| Return | ignored by Flutter; detail is read by `ticketId` | `uuid` | Compatible |
| Execute grant | Supabase authenticated user | `grant execute ... to authenticated` | Required |

Attachment manifest fields read by SQL:

| Field | Flutter source | SQL type/usage |
| --- | --- | --- |
| `storage_path` | `UploadedTicketAttachment.storagePath` | `text`, must match `<ticket_uuid>/<uploader_uuid>/<safe_file_name>` |
| `file_name` | safe file name from storage path | `text`, stored in `ticket_attachments.file_name` |
| `mime_type` | normalized local candidate MIME type | `text`, lowercased and validated |
| `size_bytes` | local file size | `bigint`, must be 1..10485760 |

Flutter also sends `id`, `extension`, and `source`. The migration ignores those fields, so they do not break the SQL contract.

## Read-Only Production Audit SQL

Run this in Supabase production SQL Editor. It only reads catalog/application metadata.

```sql
with expected_functions as (
  select *
  from (values
    ('create_ticket_with_attachments', 'uuid, text, text, text, jsonb'),
    ('is_valid_pending_ticket_attachment_object', 'text, jsonb'),
    ('is_active_user', ''),
    ('attachment_ticket_id', 'text'),
    ('attachment_uploader_id', 'text')
  ) as item(function_name, identity_arguments)
),
function_audit as (
  select
    expected.function_name,
    expected.identity_arguments as expected_identity_arguments,
    proc.oid is not null as exists,
    pg_get_function_identity_arguments(proc.oid) as actual_identity_arguments,
    pg_get_function_arguments(proc.oid) as actual_arguments,
    pg_get_function_result(proc.oid) as return_type,
    proc.prosecdef as security_definer,
    has_function_privilege(
      'authenticated',
      proc.oid,
      'execute'
    ) as authenticated_can_execute
  from expected_functions expected
  left join pg_proc proc
    on proc.proname = expected.function_name
   and pg_get_function_identity_arguments(proc.oid) = expected.identity_arguments
   and proc.pronamespace = (
     select oid from pg_namespace where nspname = 'public'
   )
  left join pg_namespace namespace
    on namespace.oid = proc.pronamespace
)
select
  'function' as check_group,
  function_name as object_name,
  exists,
  expected_identity_arguments,
  actual_identity_arguments,
  actual_arguments,
  return_type,
  security_definer,
  authenticated_can_execute
from function_audit
order by function_name;

select
  'table' as check_group,
  'public.ticket_attachments' as object_name,
  to_regclass('public.ticket_attachments') is not null as exists;

select
  'column' as check_group,
  'public.tickets.deleted_at' as object_name,
  exists (
    select 1
    from information_schema.columns
    where table_schema = 'public'
      and table_name = 'tickets'
      and column_name = 'deleted_at'
      and data_type = 'timestamp with time zone'
  ) as exists;

select
  'bucket' as check_group,
  id as object_name,
  not public as private_bucket,
  file_size_limit,
  allowed_mime_types
from storage.buckets
where id = 'tickets';

select
  'storage_policy' as check_group,
  policyname as object_name,
  cmd,
  roles,
  qual,
  with_check
from pg_policies
where schemaname = 'storage'
  and tablename = 'objects'
  and policyname in (
    'ticket_objects_select_scope',
    'ticket_objects_insert_scope',
    'ticket_objects_delete_scope',
    'ticket_objects_insert_pending_ticket_create',
    'ticket_objects_delete_unregistered_own_upload'
  )
order by policyname;

select
  'rls_policy' as check_group,
  policyname as object_name,
  cmd,
  roles,
  qual,
  with_check
from pg_policies
where schemaname = 'public'
  and tablename in ('tickets', 'ticket_attachments')
  and policyname in (
    'tickets_select_scope',
    'tickets_insert_authenticated',
    'tickets_update_scope',
    'ticket_attachments_select_scope',
    'ticket_attachments_insert_scope'
  )
order by tablename, policyname;
```

Expected result:

- `create_ticket_with_attachments` exists with identity arguments `uuid, text, text, text, jsonb`.
- Return type is `uuid`.
- `security_definer` is `true`.
- `authenticated_can_execute` is `true`.
- `ticket_attachments` exists.
- `tickets.deleted_at` exists.
- `storage.buckets.id = 'tickets'` exists and `private_bucket = true`.
- Pending-ticket storage policies exist:
  - `ticket_objects_insert_pending_ticket_create`
  - `ticket_objects_delete_unregistered_own_upload`
- Dependency functions exist:
  - `is_active_user()`
  - `attachment_ticket_id(text)`
  - `attachment_uploader_id(text)`
  - `is_valid_pending_ticket_attachment_object(text,jsonb)`

## Fallback Audit: No-Attachment Tickets Only

The current local working tree includes an uncommitted direct insert fallback in `TicketCreateFailureMapper` and `SupabaseTicketRemoteDataSourceImpl`.

Security and behavior audit:

- It is gated to PostgREST missing-function errors only: `PGRST202` or `42883`.
- It requires the error message to mention `create_ticket_with_attachments`.
- It requires `attachmentCount == 0`.
- It does not run for tickets with attachment uploads.
- It inserts into `public.tickets` through the normal Supabase authenticated client, so production RLS and triggers still enforce `user_id = auth.uid()`, `assigned_to is null`, `status = 'open'`, and active-user requirements.
- It logs a debug message that the backend is out of sync instead of hiding the drift.

This fallback can keep no-attachment ticket creation usable during a production migration gap, but it is not a substitute for applying the RPC migration. It must not become the attachment path because attachment creation requires the atomic RPC contract.

## Rollback Plan

Preferred rollback is a Supabase point-in-time restore or backup restore taken immediately before applying the migration.

If a surgical rollback is required during a maintenance window:

1. Stop client release rollout.
2. Revoke execute on the Phase 4 create functions from `authenticated`.
3. Restore previous storage object policies from the known-good migration state.
4. Drop only the Phase 4 create functions if confirmed unused by the running client.
5. Reload PostgREST schema cache.
6. Re-run read-only audit and runtime smoke tests.

Do not delete ticket or attachment data as part of rollback unless a data-specific incident review identifies corrupt rows or orphaned objects.
